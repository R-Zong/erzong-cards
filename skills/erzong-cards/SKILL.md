# 二宗卡片（erzong-cards）

把用户的内容排成一组 3:4 卡片（小红书图文、公众号贴图通用），主题是苹果风：留白、字少、颜色只点一下。
**只排版，不生图。** 不改用户的意思和结构；任何改字都先问用户。

整个流程只有四步：**谁 → 要干什么 → 怎么做 → 检查**。

---

## 一、谁：先认出场景

看用户的内容和说法，归到一个场景，按场景的排法起一组卡片（详见 `references/scenes.md`）：

| 场景 | 一组的顺序（版式编号见第二步） |
|---|---|
| 产品介绍 / 好物种草 | C01 → G02 → N01 → X03 / X01 |
| 观点笔记 | C02 → T01 → T03 → T05 |
| 教程拆解 | C02 → X05 → X02 → T04 |
| 课程笔记 / 考试重点 | C02 → T03 → X02 → T04 |
| 数据复盘 | C02 → N02 → N03 / N04 → T01 |
| 截图解读（推文、新闻、公告） | C03（只放标题 + 截图）→ 第二张起一页一个观点 |
| 旅行 / 探店 / 生活分享 | I01 → I03 → X05 → I02 |
| 长文原样做成图（"一个字都别删"） | C02 → T02（自动分页） |

入口优先级：
1. 用户说得很具体（"第一页大字封面，第二页上下对比"）→ 照他说的排。
2. 用户说了场景 → 套场景排法。
3. 都没说 → 从内容推断；推断不出就逐页按第二步判断。

两种读法先分清：
- **快速看**（默认）：卡片式，一页一件事，每页字少。内容太多时按"压缩阶梯"给建议：先拆页 → 再把补充说明挪到笔记正文 → 最后才建议精简文字（要用户确认）。
- **完整读**：用户要原文完整保留时用 T02 长文，一字不删、自动分页。

做不了的直接说：手账风、Y2K 这类重装饰、搞笑段子、促销海报、纯摄影作品集。旅行、探店、穿搭、美妆要用户给照片，不用图库硬凑。

---

## 二、要干什么：每一页选版式

**一页 = 一件事**（指内容：一个观点、一组数字、一张图）。判断顺序：**需求定版式 → 素材定变体 → 字数定方向**。

| 这一页要干什么 | 版式 |
|---|---|
| 让人点开（封面） | C01 产品封面（有产品图）、C02 大字封面（只有字）、C03 截图封面、I01 单图（照片） |
| 讲清一个观点 | T01 段落页、T05 大金句 |
| 说清几点（≤ 4） | T03 要点列表 |
| 原文一大段，不删 | T02 长文（自动分页） |
| 列清单、目录（≤ 8） | T04 清单 |
| 让人避坑（≤ 4） | T06 避坑页 |
| 收尾提问（用户要才放） | T07 结尾提问 |
| 一段话 + 1～3 个数字 | N01 上文下数 |
| 2～4 个数字 | N02 数据页 |
| 排名、占比 | N03 条形图 |
| 一张表（≤ 3 列 5 行） | N04 表格 |
| 算账、列花费 | N05 金额清单 |
| 几个要点配小图（3～6 格） | X01 便当格 |
| 拆解一个案例（2～3 块） | X02 拆解页 |
| 比较两个东西 | X03 双列对比（字少左右，字多自动上下） |
| 进度、能不能用 | X04 状态清单 |
| 教人怎么做（3～5 步） | X05 步骤流程 |
| 展示变化 | X06 改造前后（竖图左右，横图或文字上下，自动） |
| 一页讲两个产品 | G01 产品速览 |
| 一个产品 + 3 个亮点 | G02 单品亮点 |
| 晒一张照片 | I01 单图分享：`embed` 上字下图（默认）/ `full` 铺满 / `bleed` 贴顶铺开 / `note` 照片 + 小注释 |
| 2～4 张照片 | I02 照片宫格（双图、三宫格、四宫格自动） |
| 照片 + 3 个数字（人均、天数） | I03 照片 + 速览 |
| 一张宽照片横跨 2～3 张 | I04 连拼 |

每个版式的字段、容量、什么时候别用：`references/layouts.md`。

## 三、怎么做

### 1. 先跟用户确认分页（一次问完）

渲染前把这些合成**一张清单**发给用户，一次问完，不一页一页打断：
- 分几张、每张放什么、用什么版式（一行一张）。
- 放不下的地方：先说问题（带数字）→ 给一个做好的建议 → 最多 3 个选项。例："封面标题 15 个字，最多 12 个。我精简成了「……」（10 字）。也可以：① 后半句挪到副标题 ② 拆成两页。"
- 改字一律并排给"原文 / 建议"，用户不点头不改。不替用户凑内容、不加"关注我""评论区领取"之类的话。
- 长截图：先问用户 ①裁关键一段 ②底部渐隐 ③分页（三选一，不同时出）。用户不在时默认①，并在结果里说明。
- 用户要求的选项：白底、直角、深色封面、强调色、账号名（**只有用户明确要求才放账号名**）。

用户不在、没人回答时：按最合理的理解做，结果里写清楚做了哪些决定。

### 2. 写内容文件（JSON）

格式见 `references/deck-format.md`。最小例子：

```json
{
  "options": { "accent": "blue" },
  "cards": [
    { "layout": "C02", "title": "回T退订\n短信[更多了]？" },
    { "layout": "X05", "title": "短信清零\n[分三步]",
      "steps": [ { "t": "大厂 App 开免打扰", "d": "淘宝、京东后台都有" },
                 { "t": "手机打开关键词拦截", "d": "管住 106 开头的短信" },
                 { "t": "一证通查倒查留号" } ] }
  ]
}
```

文字标记：`\n` 换行，`[词]` 强调色（**每页只用一处**，通常是标题里的一个词），`**词**` 加深，`{词}` 提示橙（日期、价格这类提示，每页最多一处），`|English|` 英文点缀字体。
图片路径相对于内容文件所在的文件夹。

### 3. 出图

```bash
node <本技能文件夹>/engine/render.cjs 内容.json [输出文件夹]
```

- 先跑一次 `--check` 只看预检也可以。
- 输出：`01-大字封面.png` …、`总览.png`（一排三张，看整组统不统一）、`预览.html`。
- 第一次用要装引擎：Windows 双击 `install/安装.bat`；Mac / Linux 运行 `bash install/install.sh`。会用本机 Edge / Chrome，不另外下载浏览器。
- 平台不能运行脚本时，用简易档：`references/lite.md`。

### 4. 图片怎么处理（引擎自动做，你只要选对位置）

- **产品图**放在产品位（C01、G01、G02、X03 的 `image`）：白底、浅灰底自动换成页面底色并羽化四边，接缝为零；透明图自动裁掉空白；深色场景图放在深色封面上自动做渐隐底图。背景复杂的图引擎不处理，会提示换图。
- **主产品图不放进白色圆角块**；块里的小图可以。
- **照片**不加滤镜、不改颜色、不加边框阴影。横图放进竖版要注意主体：用 `pos`（如 `"64% 50%"`）把裁切对准主体；主体比裁切框还宽就别铺满，改用 `bleed` 贴顶或 `embed`。
- **铺满（full）只放标题**，字放在照片的安静区域（`pos: top / bottom`），字色深浅自动判断；安静区域不够就先改成两行，还不行就改 `bleed`。
- 照片为主的一组、单张卡片、铺满照片页不放翻页圆点（引擎自动）。

---

## 四、检查

出图后，**必须**：
1. 看命令行里的【预检提醒】和【质检】。质检会查：文字超出边距、文字压图、内容放不下、圆点碰字碰图、孤字、标题太靠上（要 ≥ 150px）、强调色超过一处、数字挤出栏、图片放大会糊、长截图、满版照片标题下面不够安静、缺字缺图标。
2. **自己打开 `总览.png` 和有问题的单张看一眼**（用读图工具），确认没有压字、裁到主体、整组风格不统一。
3. 修：只动版式、位置、拆页；**不降字号、不改用户文字**（要改字回第三步第 1 条问用户）。
4. 交付时说清楚：几张、存在哪、做了哪些需要用户知道的决定（比如长截图裁了哪段）。张数超过 9 张提醒：公众号图片消息发不了，小红书部分版本要分两次选。

不要做：
- 不用 Apple 的标志、产品图、SF Pro / 苹方字体；示例不放苹果产品。
- 不联网取图；用户没给图就不放图（不画假设备、不放占位假内容）。
- 别人品牌的 logo、截图，用户要公开发布时提醒一句版权。
